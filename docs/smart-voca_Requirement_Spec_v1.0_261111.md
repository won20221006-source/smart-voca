## 1. 요구사항 ID 체계

- 형식: `REQ-NNN` (3자리 순번, 예: `REQ-001`)
- 기능 요구사항: `REQ-001`~`REQ-099`
- 비기능 요구사항: `NFR-001`~`NFR-099`
- 구현 코드·테스트·커밋 메시지에는 해당 REQ-ID를 명시한다 (CLAUDE.md 코드 규칙 10).

## 2. 기능 요구사항

### 2.1 단어장 관리 (BR-01)

| ID | 요구사항 | 수용 기준 (Acceptance Criteria) | 우선순위 |
|----|----------|-------------------------------|----------|
| REQ-001 | 단어장을 생성할 수 있다 | 이름(필수, 1~50자)을 입력하면 단어장이 저장되고 목록에 표시된다 | 상 |
| REQ-002 | 단어장 목록을 조회할 수 있다 | 전체 단어장과 각 단어장의 단어 수가 표시된다 | 상 |
| REQ-003 | 단어장 이름을 수정할 수 있다 | 수정 후 목록과 상세에 새 이름이 반영된다 | 중 |
| REQ-004 | 단어장을 삭제할 수 있다 | 삭제 전 확인 창이 뜨고, 확인 시 단어장과 소속 단어·학습 기록이 함께 삭제된다 | 중 |

### 2.2 단어 관리 (BR-01)

| ID | 요구사항 | 수용 기준 | 우선순위 |
|----|----------|-----------|----------|
| REQ-005 | 단어장에 단어를 추가할 수 있다 | 단어(필수, 1~100자)와 뜻(필수, 1~200자)을 입력하면 해당 단어장에 저장된다 | 상 |
| REQ-006 | 단어의 예문을 입력·저장할 수 있다 | 예문은 선택 항목이며, 입력 시 단어 상세에 표시된다 | 중 |
| REQ-007 | 단어 목록을 조회할 수 있다 | 단어장 선택 시 소속 단어가 단어·뜻·예문과 함께 표시된다 | 상 |
| REQ-008 | 단어를 수정할 수 있다 | 단어·뜻·예문 수정 후 목록에 반영된다 | 중 |
| REQ-009 | 단어를 삭제할 수 있다 | 삭제 전 확인 창이 뜨고, 확인 시 단어와 학습 기록이 삭제된다 | 중 |
| REQ-010 | 같은 단어장 안에서 중복 단어를 막는다 | 같은 단어장에 동일한 단어(대소문자·앞뒤 공백 무시)를 추가하면 경고를 표시하고 저장하지 않는다 | 중 |

### 2.3 학습 세션 (BR-02)

| ID | 요구사항 | 수용 기준 | 우선순위 |
|----|----------|-----------|----------|
| REQ-011 | 단어장 단위로 학습 세션을 시작할 수 있다 | 세션 시작 시 해당 단어장의 단어가 순서대로 카드로 제시된다 | 상 |
| REQ-012 | 카드를 뒤집어 뜻을 확인할 수 있다 | 카드 앞면은 단어, 뒷면은 뜻과 예문을 표시한다 | 상 |
| REQ-013 | 카드마다 정답/오답을 입력할 수 있다 | 입력 시 결과가 학습 기록에 저장되고 다음 카드로 넘어간다 | 상 |
| REQ-014 | 세션 종료 시 결과 요약을 보여준다 | 학습한 단어 수, 정답 수, 정답률이 표시된다 | 중 |
| REQ-015 | 학습 결과는 시각과 함께 기록된다 | 단어별 학습 이력(일시, 정답 여부)이 저장된다 | 상 |

### 2.4 복습 스케줄러 (BR-02)

| ID | 요구사항 | 수용 기준 | 우선순위 |
|----|----------|-----------|----------|
| REQ-016 | 학습 결과에 따라 다음 복습 날짜를 계산한다 | 정답 시 다음 간격으로 늘어나고, 오답 시 짧은 간격(1일)으로 되돌아간다 | 상 |
| REQ-017 | MVP 복습 간격은 고정 규칙을 사용한다 | 간격 규칙(제안: 정답 시 1→3→7→14→30일, 오답 시 1일)을 설정 파일 상수로 두고 코드에 직접 쓰지 않는다 | 상 |
| REQ-018 | 복습 간격 규칙은 교체할 수 있게 분리한다 | 스케줄 계산 로직이 단일 모듈에 있고, 알고리즘 교체 시 호출부를 수정하지 않는다 | 중 |

> **주의**: REQ-016~017의 간격 값은 제안값이다. 기획서 §9-4(간격 반복 알고리즘 직접 구현 여부)에 대한 답을 받은 뒤 확정한다.

### 2.5 오늘의 복습 목록 (BR-03)

## 3. 비기능 요구사항

| ID | 구분 | 요구사항 | 측정 기준 |
|----|------|----------|-----------|
| NFR-001 | 실행 환경 | 로컬 PC에서 한 명령으로 실행할 수 있어야 한다 | 설치 후 서버 기동까지 README 절차로 재현 가능 |
| NFR-002 | 데이터 저장 | 학습 데이터는 SQLite 파일 1개에 저장된다 | DB 파일 복사만으로 백업 가능 |
| NFR-003 | 성능 | 단어 1,000개 규모의 단어장에서 목록 화면이 1초 안에 표시된다 | 로컬 측정 |
| NFR-004 | 보안 | 비밀정보(키·DB 접속정보)는 `.env`로 관리하고 코드에 쓰지 않는다 | CLAUDE.md 코드 규칙 5 |
| NFR-005 | 개인정보 | 학습자 이름·연락처를 수집하지 않는다 | 입력 폼에 해당 항목 없음 |
| NFR-006 | 사용성 | 주요 화면(단어장, 학습, 복습 목록)을 데스크톱 브라우저에서 사용할 수 있다 | 최신 Chrome·Edge에서 동작 |
| NFR-007 | 유지보수 | 스케줄 계산, 정답률 계산 등 핵심 로직은 웹 계층과 분리되어 단위 테스트가 가능하다 | 테스트 정의서에서 단위 테스트 대상 |

| NFR-009 | 데이터 무결성 | 단어장 삭제 시 소속 단어와 학습 이력이 함께 정리되어 고아 데이터가 남지 않는다 | DB 제약 조건(FK, CASCADE) 확인 |

## 5. 확인 결과 (2026-11-18, 사용자 위임으로 MVP 기준 확정)

1. **로그인 필요 여부 (기획서 §9-5)**: 로그인 없음. REQ-025 적용, REQ-026 보류 유지. 근거: `Decision_Records §6-2`
2. **복습 간격 방식 (기획서 §9-4)**: 고정 간격(REQ-017 제안값) 확정. 계산기는 인터페이스로 분리(REQ-018). 근거: `Decision_Records §6-1`
3. **학습 세션 방식**: 정답/오답 직접 선택(REQ-013) 확정. 뜻 입력 방식은 후속 과제. 근거: `Decision_Records §6-3`

새로 정한 가정 (요구사항 본문과 다르게 구현된 부분):
- 새 단어의 첫 복습일은 추가한 날 (REQ-019 해석). 근거: `Decision_Records §6-4`
- 예문(REQ-006)의 길이 제한은 두지 않음
